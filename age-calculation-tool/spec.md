# 年齢計算ツール 要件定義書・機能設計書

## 1. 概要

### 1.1 ツール名

年齢計算ツール（age-calculation-tool）

### 1.2 目的

生年月日と基準日を入力することで、指定日時点の年齢を以下の形式で確認できる静的Webツールを作成する。

- 満年齢
- 数え年
- 生後日数
- 次の誕生日までの日数

「今日時点の年齢」だけでなく、「過去または未来の特定日時点の年齢」も確認できることを目的とする。

### 1.3 想定利用シーン

- 履歴書、申請書、社内資料などで年齢を確認したい場合
- 特定日付時点の年齢を調べたい場合
- 数え年を使う行事、年祝い、厄年などの参考情報として利用したい場合
- 生年月日から年齢や生後日数を手早く算出したい場合

### 1.4 対象プラットフォーム

| 項目 | 内容 |
| --- | --- |
| 実行環境 | Webブラウザ |
| 公開形態 | 静的Webサイト |
| 想定公開先 | GitHub Pages |
| 使用技術 | HTML / CSS / JavaScript |
| サーバー処理 | なし |
| データ保存 | なし |

## 2. 要件定義

### 2.1 業務要件

#### 2.1.1 基本方針

本ツールは、生年月日と基準日をもとに、基準日時点の年齢情報を計算する。

基準日はデフォルトで今日の日付を設定する。

ユーザーは必要に応じて基準日を任意の日付に変更できる。また、「今日」ボタンを押すことで、基準日を今日の日付に戻すことができる。

#### 2.1.2 年齢の定義

##### 満年齢

満年齢は、生年月日から基準日までに何回誕生日を迎えたかで計算する。

例：

- 生年月日：2000年5月22日
- 基準日：2026年5月21日
- 満年齢：25歳

##### 数え年

数え年は、生まれた年を1歳とし、以後、年が変わるごとに1歳加算する方式とする。

本ツールでは、以下の計算式を基本とする。

```text
数え年 = 基準年 - 生年 + 1
```

例：

- 生年月日：2000年5月22日
- 基準日：2026年5月21日
- 数え年：27歳

#### 2.1.3 日付の扱い

日付は年月日単位で扱い、時刻は扱わない。

ブラウザやタイムゾーン差異による日付ずれを避けるため、JavaScriptの `Date` オブジェクトを直接文字列パースするのではなく、年・月・日を分解してローカル日付として扱う。

#### 2.1.4 うるう日生まれの扱い

2月29日生まれの満年齢計算については、仕様として明示する必要がある。

本ツールでは、初期仕様として以下の方式を採用する。

- うるう年ではない年の誕生日相当日は「2月28日」として扱う

例：

- 生年月日：2000年2月29日
- 基準日：2026年2月28日
- 満年齢：26歳

### 2.3 非機能要件

#### 2.3.1 パフォーマンス

- 入力後、すぐに計算結果を表示できること
- 外部APIへの通信を行わないこと
- 通常利用時、ページ表示および計算処理で体感的な遅延がないこと

##### 2.3.2 セキュリティ

- 入力された生年月日をサーバーに送信しないこと
- 入力内容を外部サービスへ送信しないこと
- Cookie、LocalStorage、SessionStorageに生年月日を保存しないこと
- 外部ライブラリを使用する場合は、信頼できるものに限定すること

#### 2.3.3 プライバシー

生年月日は個人情報に該当し得るため、以下の方針とする。

- 計算処理はブラウザ内で完結させる
- 入力値を保存しない
- アクセス解析を導入する場合でも、入力値を収集しない

#### 2.3.4 可用性

- GitHub Pagesで公開できること
- HTML、CSS、JavaScriptのみで動作すること
- サーバーサイド処理を必要としないこと

#### 2.3.5 保守性

- 年齢計算ロジックは独立した関数として実装する
- 画面制御と計算ロジックを分離する
- テストしやすいように、計算関数は入力値と戻り値が明確な形にする

#### 2.3.6 アクセシビリティ

- ラベルと入力欄を適切に関連付ける
- キーボード操作だけでも利用できるようにする
- エラーメッセージを視覚的にも文言的にも分かりやすく表示する
- コントラストの低すぎる配色を避ける

#### 2.3.7 レスポンシブ対応

- PC、タブレット、スマートフォンで利用できること
- スマートフォンでは入力欄とボタンが縦並びで見やすいこと

---

### 2.4 対象外

初期リリースでは、以下は対象外とする。

- 生年月日の保存機能
- 複数人の年齢一覧計算
- CSVインポート／エクスポート
- 厄年、長寿祝い、学年などの詳細判定
- 和暦入力
- 多言語対応
- サーバーサイド処理
- ユーザー認証
- 前回の誕生日からの日数計算

ただし、将来的な拡張候補としては検討可能とする。

#### 3.5.2 計算するボタン押下処理

### 3.6 計算ロジック設計

#### 3.6.1 満年齢計算

##### 入力

- 生年月日
- 基準日

##### 出力

- 満年齢

##### ロジック

```text
満年齢 = 基準年 - 生年

基準日の月日が、生年月日の月日より前の場合、満年齢から1を引く。
```

##### 例

| 生年月日 | 基準日 | 満年齢 |
| --- | --- | --- :|
| 2000-05-21 | 2026-05-21 | 26 |
| 2000-05-22 | 2026-05-21 | 25 |
| 2000-01-01 | 2026-05-21 | 26 |

---

#### 3.6.2 数え年計算

##### 入力

- 生年月日
- 基準日

##### 出力

- 数え年

##### ロジック

```text
数え年 = 基準年 - 生年 + 1
```

##### 例

| 生年月日 | 基準日 | 数え年 |
| --- | --- | --- :|
| 2000-05-21 | 2026-05-21 | 27 |
| 2000-12-31 | 2026-01-01 | 27 |
| 2026-05-21 | 2026-05-21 | 1 |

---

#### 3.6.3 生後日数計算

##### 入力

- 生年月日
- 基準日

##### 出力

- 生後日数

##### ロジック

```text
生後日数 = 基準日 - 生年月日
```

日付差はミリ秒差から算出する場合、時刻やサマータイムの影響を避けるため、UTC基準の日付値に変換して計算する。

```text
生後日数 = (UTC基準日 - UTC生年月日) / 1日のミリ秒数
```

---

#### 3.6.4 次の誕生日までの日数計算

##### 入力

- 生年月日
- 基準日

##### 出力

- 次の誕生日までの日数

##### ロジック

1. 基準年における誕生日を作成する
2. 基準日が誕生日以前の場合、その日付を次の誕生日とする
3. 基準日が誕生日より後の場合、翌年の誕生日を次の誕生日とする
4. 基準日から次の誕生日までの日数を計算する

##### 補足

基準日が誕生日当日の場合は、日数ではなく「今日が誕生日です」と表示する。

---

#### 3.6.5 うるう日生まれの誕生日相当日

生年月日が2月29日で、対象年がうるう年ではない場合は、2月28日を誕生日相当日として扱う。

##### ロジック

```text
生年月日が2月29日 かつ 対象年がうるう年ではない場合
  誕生日相当日 = 対象年2月28日
それ以外
  誕生日相当日 = 対象年の生年月日と同じ月日
```

### 3.11 将来的な拡張候補

#### 3.11.1 和暦対応

西暦だけでなく、明治・大正・昭和・平成・令和による入力や表示に対応する。

### 3.11.2 厄年判定

数え年をもとに、男性・女性別の厄年を判定する。

#### 3.11.3 長寿祝い判定

還暦、古希、喜寿、傘寿、米寿、卒寿、白寿などの長寿祝いを判定する。

#### 3.11.4 学年・入学年度計算

生年月日から学年や入学年度を計算する。

#### 3.11.5 複数人一括計算

CSVや表形式で複数人の生年月日を入力し、年齢を一括計算する。

## 4. 実装方針

### 4.1 ファイル構成案

```text
age-calculator/
  index.html
  css/
    style.css
  js/
    main.js
  README.md
```

小規模ツールとして管理する場合は、以下のように1ファイル構成でもよい。

```text
age-calculator/
  index.html
```

ただし、保守性を考えると、HTML・CSS・JavaScriptは分離する方が望ましい。

---

### 4.2 GitHub Pages公開方針

GitHub Pagesで公開するため、以下の構成を想定する。

- リポジトリに `index.html` を配置する
- 必要に応じて `css/style.css`、`js/main.js` を配置する
- GitHub Pagesの公開ブランチは `main` ブランチを想定する
- 公開元はリポジトリ直下、または `/docs` フォルダを選択する

---

### 4.3 実装時の注意点

- `new Date("YYYY-MM-DD")` の直接利用は避ける
- 日付差分計算はUTC基準で行う
- 2月29日生まれの扱いをコメントで明記する
- 計算ロジックはDOM操作から分離する
- 入力された生年月日を保存しない
- スマートフォンでも押しやすいボタンサイズにする
